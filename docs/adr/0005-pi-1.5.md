# ADR 0005: Pi 1.5.0

Date: 2026-11-02. Status: accepted. Spec: 0001, "JS toolchain" and the parked-task row of the Pi feature table.

## Context

pi-durable, pi-ai and chord 1.5.0 change APIs the app uses:

- `watchEvents()` and `Conversation.viewState()` are gone. `Conversation.watch()` replaces both. Its `entries` are a
  window (the newest 50, at most 100) over the fork-aware history, not the whole active transcript.
- Tool schemas are JSON Schema from `@earendil-works/pi-schema`; pi-ai no longer exports TypeBox's `Type`.
- `SqliteExecutor` gains `runCounted`; `onReport` takes one `Report` tagged by `kind`.
- Restart-limited tasks no longer park: they end, so `Harness.retryTask()` is gone. A model request cut off by a
  crash counts as a failed attempt under the retry policy and is resent after its backoff.

## Decision

- Pin pi-durable, pi-ai, pi-schema and chord to 1.5.0.
- Keep the chat's frame contract with Swift (the first frame holds the whole transcript, later frames append).
  `js/src/app/view.ts` merges each watch value into a `ConversationTranscript` and pages in earlier entries and gaps
  until the history is complete. The chat now shows the full history: messages before a compaction or a reset
  stay, under their notice.
- Code that needs what the model sees (the `web_fetch` trust check, the kill test's `settle`) reads
  `Conversation.context()`. The steer path reads `pi.inbox` and `pi.live` with `snapshot()`.
- Tool schemas use pi-schema's builders. `obj` is closed by default, unlike `Type.Object`, so a call with an
  unknown argument gets an `invalid_arguments` result the model can correct.
- Diagnostics drops the parked state and its Retry button; Abort stays.
- `runCounted` returns `sqlite3_changes()` from Swift's `sqliteRun`; `js/test/facade-cases.ts` checks it.

## Consequences

- A long conversation's first frame pages its history in 200-entry pages, as `viewState()` used to load it at once.
- `pi.live.runFailure` (why a run ended without an answer) is not shown yet; frames still carry assistant error
  entries as before.
